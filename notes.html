Notes · Hotel Operations Knowledge Assistant (independent, simulated engagement)

My eval said 96%. It was wrong.

The number was real. It just measured something easier than what the front desk needs.

The setup

The hotel assistant answers front-desk policy questions from each hotel's documents. Before any answer is written, search has to find the right passage, so the first thing I measured was retrieval: for each labeled question, is the right source in the top 5 results?

After adding light stemming (so “cats” matches “cat” and “RVs” matches “RV”), keyword search reached 96% on that check, up from 86%.

The question that shouldn't have passed

One test question is in Spanish: “¿Se permiten perros en el hotel?” Keyword search shares no words with the English documents, so every passage scored zero. It passed anyway. With every score tied at zero, results came back in file order, and the right document happened to be first.

The check only asked whether the right document appeared somewhere in the top 5. It never asked whether the passage with the answer was there.

The fix

  • Each question now names a distinctive phrase, such as “up to 40 lbs”, that must appear in a retrieved passage from the expected document. Multi-part questions list one phrase per part.
  • Search never returns passages that match nothing. A question with no matching words gets a refusal without calling the model, instead of five arbitrary passages.

The honest keyword-only score on that 37-question set was 94% (32 of 34 answerable questions). Lower, and true.

What I took from it

  • Measure what the user needs. Staff need the passage with the answer, not the right file name.
  • Check that a metric can fail. A test that passes on a question with zero matches is measuring luck.
  • Read the raw results, not just the score. The same habit later caught my answer grader passing a wrong “yes”.

Today the eval has 54 questions in 16 categories, and strict retrieval is 98% (44 of 45) in both search modes. The Spanish question still fails in keyword mode, and it's documented as a known limitation.

Sources: the project's decision log (decisions 7 to 10) and eval reports in the repository.
