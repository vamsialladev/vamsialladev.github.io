02 · One engagement, stage by stage

One engagement, stage by stage

Each stage builds on the last and delivers something a client could use on its own. Stages 0–5, 7 and 8 are published.

  1. 0

    Discovery & Scoping

    The discovery, problem selection, statement of work, pricing model and security questionnaire that came before any code.

  2. 1

    Hotel Operations Knowledge Assistant

    Front-desk staff ask policy questions and get cited, property-specific answers, or an honest "check with a manager".

  3. 2

    Guest Request Agent

    An agent that reads guest emails, checks bookings and policy (using stage 1 as a tool) and drafts a reply that staff approve before anything is sent.

  4. 3

    Eval Harness

    One evaluation system for stages 1 and 2: 181 labelled cases, the projects' own metrics, regression gates in both repos' CI, and an LLM judge that counts only once it agrees with hand labels.

  5. 4

    Production Deployment

    Both live apps hardened: four gaps the evals found fixed and measured, personal data redacted before storage, a staff role, latency and cost budgets gated in CI, a kill switch and an Operations page.

  6. 5

    Client Handoff

    A handoff package for the hotel group's IT and operations teams: architecture, decision index, eight runbooks, SLOs and budgets, staff and admin guides, a readiness checklist, a 30/60/90-day plan and a daily health check.

  7. 7

    Hotel Tools MCP Server

    An MCP server where an API key's role decides which tools exist and which fields come back, hotel groups can't see each other's data, and every call is audited.

  8. 8

    Ops Analytics Agent

    Managers ask the bookings database in plain English and see the SQL behind every answer; a daily check posts anomalies to Slack.
